# Harbor registry — air-gapped

Deploys Harbor as containers from its official offline installer, on a RHEL
host, in an environment with no internet access. Follows the repo conventions:
single-purpose roles with the `desired_state` dispatcher, a paved-path playbook,
and everything environment-specific in `group_vars` and `host_vars`.

---

## The flow

```
unclassified, connected         transfer          each air-gapped environment
-----------------------         --------          ---------------------------
make stage-harbor          ->   media / diode ->  Nexus or Artifactory  ->  make linux-registry
  installer + sha256                              (artifact_source: repo)
  harbor_artifacts.yml                        or  attached storage       ->  make linux-registry
  optional PUT to a repo                          (artifact_source: staged)
```

Each environment has its own inventory, its own `group_vars/all/artifacts.yml`
and its own vault. Nothing is shared between environments.

---

## Roles

| Role | Runs | What it does |
|---|---|---|
| `stage_harbor_artifacts` | connected side | Downloads the installer, writes `harbor_artifacts.yml`, optionally pushes to a repository |
| `install_docker_offline` | registry host | Docker Engine and Compose from the environment yum repo or staged RPMs |
| `download_harbor_artifacts` | registry host | Pulls or copies the installer, verifies sha256 |
| `configure_harbor_tls` | registry host | IdM certificate with certmonger renewal, or staged certificate |
| `install_harbor` | registry host | Unpacks, writes `harbor.yml` from the shipped template, runs `install.sh`, systemd unit |
| `configure_harbor_projects` | registry host | Creates `sup-services`, `tanzu-packages`, `tkg` through the API |
| `verify_harbor` | registry host | Read-only checks |

All of them honour `desired_state: present | absent`.

## Variables by scope

### `group_vars/all/artifacts.yml` — environment-wide

| Variable | Required? | What it is |
|---|---|---|
| `artifact_source` | **REQUIRED** | `repo` or `staged` |
| `artifact_repo_url` | **REQUIRED if** `repo` | Nexus raw hosted or Artifactory generic base URL |
| `artifact_repo_username` / `_password` | optional | From `vault_repo_username` / `vault_repo_password` |
| `artifact_repo_headers` | optional | Token headers, e.g. `Authorization: Bearer …` for Artifactory |
| `artifact_repo_validate_certs` | optional | Default `true` |
| `artifact_staging` | **REQUIRED if** `staged` | Already in `group_vars/all/main.yml` |
| `artifact_staged_on` | optional | `target` (default) or `controller` |

Expected layout under the repository URL or the staging mount:

```
harbor/
  harbor-offline-installer-v<version>.tgz
  harbor_artifacts.yml
  docker/*.rpm                      only if docker_offline_source: staged
  tls/<harbor_hostname>.crt|.key    only if harbor_tls_mode: staged
```

### `group_vars/registry/main.yml` — registry tier

| Variable | Default | What it is |
|---|---|---|
| `harbor_projects` | the three projects | Created through the API |
| `harbor_data_volume` | `/data` | Registry storage |
| `harbor_http_port` / `harbor_https_port` | `80` / `443` | Listeners |
| `harbor_with_trivy` | `false` | No vulnerability feed inside |
| `harbor_tls_mode` | `ipa` | `ipa` or `staged` |
| `docker_offline_source` | `yum` | `yum` or `staged` |
| `firewall_open_tcp_ports` | `22, 80, 443` | Opened in `post_tasks` when `enable_firewall` |

### `group_vars/registry/harbor_artifacts.yml` — release

Generated by `make stage-harbor`. Holds `harbor_version`,
`harbor_installer_file` and `harbor_installer_sha256`. Replace it to upgrade.

### `host_vars/<registry host>.yml`

| Variable | Required? | What it is |
|---|---|---|
| `harbor_hostname` | **REQUIRED** | The name clients and the Supervisor use |
| `harbor_data_volume` | optional | Point at a separate disk |
| `artifact_source` | optional | Override the environment choice for this host |

### `group_vars/all/vault.yml`

`vault_harbor_admin_password`, `vault_harbor_db_password`, and the existing
`vault_repo_username` / `vault_repo_password`.

## Running it

Connected side, once per Harbor release:

```bash
make stage-harbor STAGE_ARGS="-e stage_harbor_version=2.14.0 \
  -e stage_harbor_push=true \
  -e stage_harbor_repo_url=https://nexus.example.coach/repository/vmware-raw"
```

Inside each environment:

```bash
cp artifacts/harbor/harbor_artifacts.yml inventory/group_vars/registry/
make linux-registry HOST=registry01.example.coach
make verify-registry HOST=registry01.example.coach
```

Upgrading Harbor later: stage the new release, replace `harbor_artifacts.yml`,
run `make linux-registry`. `install_harbor` sees the version change and follows
Harbor's upgrade procedure — stop, copy the database, unpack, migrate
`harbor.yml`, reinstall. Rehearse it in the lowest environment first, and check
Harbor's release notes for the supported version jump.

---

## Before the first run

- Mirror the Docker CE packages into the environment's yum repository, or stage
  the RPMs and set `docker_offline_source: staged`.
- For `harbor_tls_mode: ipa`, the host is an IdM client and the service
  principal exists: `ipa service-add HTTP/registry.example.coach`.
- Create forward and reverse DNS for `harbor_hostname`.

## After the first run

1. Push content with the existing scripts, pointed at `harbor_hostname`.
2. Add the registry, with the IdM CA, under Supervisor → Configure → Container Registries.
3. Register each Supervisor Service from it as the service is upgraded.

## Deliberate choices

- **Docker, not Podman.** Harbor's installer is built around Docker Engine and Compose.
- **Trivy off.** Its database needs an internet feed.
- **No backup role.** Content is re-pushed from the transfer kit.
- **`harbor.yml` from the shipped template.** Only a handful of values change,
  so the file stays correct across Harbor releases.
